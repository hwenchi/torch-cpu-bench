You might not need a GPU

Benchmarking PyTorch inference on a few CPU cores

Background

Modern x86 CPUs offer multiple cores and SIMD instruction sets such as AVX2 and, on supported processors, AVX-512, which accelerate numerical computations by processing multiple data elements per instruction. PyTorch takes advantage of these capabilities through optimized libraries and native CPU kernels. Matrix multiplications can use Intel oneMKL, while convolutions and other operations may use oneDNN or specialized PyTorch implementations. Many operations can also run in parallel across CPU cores using OpenMP.

PyTorch's torch.compile, powered by TorchInductor by default, can further improve performance by fusing operations, generating optimized C++ and OpenMP kernels, and exploiting CPU vector instructions to reduce overhead and memory traffic. Depending on the operation and backend, compiled inference can also use optimized external libraries.

These capabilities raise an important question: how well can modern deep-learning models run on just a few CPU cores? We investigate this by benchmarking , comparing standard PyTorch execution with torch.compile under limited CPU resources.

Experiment

Limitations

Scope. We measured individual forward passes rather than end-to-end application workloads. Processing datasets, serving concurrent requests, and generating text or images involve repeated model executions and may have different performance characteristics. We evaluated language models using a 128-token prompt and diffusion models using a single denoising step rather than a complete generation. We did not evaluate training. Therefore, our results demonstrate the potential of CPU-based inference for certain workloads, rather than suggesting that CPUs can replace GPUs in every scenario.

Measurement and performance metrics. We conducted all benchmarks on a single compute node, so results may differ across CPU architectures and cluster configurations. We evaluated models using 32-bit floating-point precision without quantization, which can improve inference speed and reduce memory requirements in deployed systems. Our reported GFLOPs count only matrix multiplications, convolutions, and attention operations. As a result, they underestimate the computational work of models that rely heavily on other operations, including graph neural networks, recommendation systems, Mamba models, and object detection architectures.
