You might not need a GPU

Background

GPUs are widely used for deep learning, particularly for large-scale training and computationally intensive inference. However, on shared clusters, they may be more expensive and less readily available than CPUs. Whether a GPU is worthwhile depends on the workload and the performance gains it provides relative to its cost. Two useful factors to consider are the computational demands of each model execution and the number of times the model must run. The first depends on factors such as model size and input size, as in large language models, diffusion models, high-resolution images, videos, and long documents. The second depends on how often the model runs, as in training, processing large datasets, serving high request volumes, and generating text or images token by token or through iterative denoising. When computational demands are modest and throughput requirements are low, CPU inference may be sufficient and more cost-effective. Modern CPUs offer multiple cores and, depending on the processor, vector instruction sets such as AVX2 and AVX-512. Optimized libraries such as oneDNN and oneMKL can further improve performance, making CPU-based inference a practical alternative for suitable workloads.

Limitations

All timings come from a single node. Each measurement covers one forward pass, so the language models were timed processing a 128-token prompt rather than generating text token by token. All models ran in 32-bit precision without quantization, which tuned deployments often use to run faster. The GFLOPs figures count only matrix multiplications, convolutions and attention, so graph, recommendation, Mamba and detection models do more work than their GFLOPs suggest.
